## 1. 机制

一个人物持有一种物品（或钱），每一步是**同一种事件**：

> "If Mia has more than 45 stickers, she gives 12 of them to a friend; otherwise, she buys 9 more."

- 先把**当前数量**与阈值 T 比较（严格大于/小于，生成时保证当前值 ≠ T，所以不存在"等于"歧义）；
- 大于 T 走"减少"分支（−a），小于 T 走"增加"分支（+b）；
- 答案是 d 个事件全部执行完后的数量（单个数字，并行版为多个数字）。

每一步都只有"一次比较 + 一次两位数加或减"，与 GSM8K 的加减应用题同属一类运算，但步数 d 可精确控制在 1..20。

## 2. 为什么没有捷径（no aggregation）

纯加减链满足结合律，DA 可以"把所有数一次加总"跳过中间状态。这里每一步**选哪个数、用加还是减**由
上一步结果决定，所以不知道第 k−1 步的值就无法确定第 k 步的操作。生成器对以下"偷懒策略"做了实测
（`python generate.py --mode check --n 500`，每个 d 500 题，共 1 万题，整数版）：

| 偷懒策略 | 命中正确答案的比例 |
|---|---:|
| 题中所有数字直接相加 | 0.0000 |
| 忽略条件、两个分支都执行（初值 + 所有 b − 所有 a） | 0.0084 |
| 永远走"减少"分支 | 0.034（全部来自 d≤2，d≥3 为 0，已拒绝采样） |
| 永远走"增加"分支 | 0.040（同上） |
| 答案原样出现在题干里（可抄） | 0（不过滤时 0.0042，已拒绝采样） |
| 用最后一个阈值 T±a/b 猜 | 0.019 |
| 答案等于初值 | 0 |
| 任意一步走错分支后仍碰巧得到正确答案 | 0.027（每步） |

两位小数版对应比例更低（全部 ≤0.04，"最后阈值猜测"0.0002，"走错一步仍正确"0.0004）。
d=1 时"永远减/永远加"各约 50% 是题型本身决定的（只有两个分支），不算捷径。

**已知的软泄漏**：阈值 T 是在当前值 ±(3..40) 范围内选的，所以 T 序列大致暴露了状态的量级，DA 可以
"猜个差不多"，但要猜中**精确值**需要真的算完（上表 0.019）。如果担心，可把 margin 上限再放大。

## 3. 单步难度控制（目标 p1 = DA(d=1) ≈ 0.85–0.95，理想 0.955–0.986）

单步难度在所有 d 上保持同分布，没有随深度变难的成分：

| 旋钮（`BASE_CFG`） | 默认 | 作用 |
|---|---|---|
| `start_min/max` | 20–120 | 初值 |
| `val_min/max` | 0–200 | 所有中间值的硬边界，越界的步骤会被重新抽样，**不会出现负数/溢出** |
| `delta_min/max` | 2–29 | 每步加减量 a、b（两位数以内，有进位/借位） |
| `margin_min/max` | 3–40 | \|当前值 − T\| 的范围，越小比较越难 |
| `decimals` | 0 | 0=整数；1/2=钱（$），见第 4 节 |
| `ops` | addsub | 唯一运算。乘法 / `mixed`（翻倍）已从生成路径删除，命令行也不能再打开 |
| `p_distractor` | 1.0 | 每题 1 句干扰数字（年龄、班级人数、别人的物品等），模仿 GSM8K |
| `p_mul2` | 0.2 | **不读取**。留在 `config` 里只为与已交付样例、校准集的字段一致 |

调难度的顺序建议：先调 `delta_max`（9 → 29 → 99），再调 `margin_min`，最后才开小数。
不使用乘法。依据 task.md「提难度靠多一个状态而不靠更难的算子」。

## 4. 小数（钱）选项

`--decimals 1` 或 `--decimals 2`：题目改成钱的情境（"Mia has $43.70 ... she spends $16.87 on a snack"）。

- **精确计算**：内部全部用整数（分）运算，`Num.fmt` 只在输出时格式化，没有浮点误差；
  初值和每步加减量的小数部分强制非零，保证真的要处理小数；阈值 T 取整数美元（"more than $45"），比较依然严格。
- **评分**：`grade(pred, gold, decimals)`：去掉 `$`、逗号和空格后用 `Decimal` 解析，容差为最小单位的一半
  （整数 0.5，两位小数 0.005），所以 `3.5 == 3.50 == $3.50`；并行题按顺序逐个比较。
- **对难度的预期**：小数加减多了一次小数位对齐和跨位进位（如 65.00−16.87），DA 单步正确率会明显下降，
  我们估计比整数版低 5–15 个百分点（**未实测**）。如果整数版 p1 太高（≥0.99，CoT(20) 回到天花板），
  小数是最自然的提难旋钮；如果整数版 p1 已在窗口内，就不建议开。

## 5. d 与并行 w 的构造（与现有管线一致）

- **串行**：d=1..20，每格 100 题，一个人物、d 个事件，`W = W_atomic = d`。
- **并行**：w=1..10，每格 100 题，w 个人物各自独立一条链，链长 `[1,2,2,...,2]`，
  所以 `W = 2w−1`，与串行奇数 d=1..19 配平，实际最长依赖深度 ≤2（与 pointer 版相同）。
  题干长度也与配平的串行题接近（w=10 约 2300 字符，串行 d=19 约 2100–2300 字符）。
- 拒绝采样：每条链的答案不得出现在本段题干数字中；d≥3 时不得等于"永远减/永远加/初值"的结果；qid 不重复。
- 生成完全确定（`random.Random(f"{seed}|{version}|{config}|{kind}|{x}|{i}")`），每次运行都会重建一遍比对 qid。
- 自检：独立求解器只用题面上的参数（T、a、b、分支类型）复算答案；检查所有中间值在边界内、无负数、无平局。

## 6. 字段（与 `synthesis_pointer_numeric_dataset.jsonl` 对齐）

保留：`version, seed, config, split, kind, d, w, i, task_family, qid, W, W_atomic, matched_serial_d,
chain_lengths, ans, answers, q, chains`。

- `ans`：字符串，并行为逗号分隔；小数版固定位数（如 `"80.80"`）。`answers`：数值列表。
- 新增 `solution`（GSM8K 风格 gold：每步一行 `80 > 44, so Ethan loses 25: 80-25=<<80-25=55>>55`，最后 `#### N`）、
  `answer_decimals`、`grading`。
- `chains[*]`：`name, item, initial, steps, events[{T,a,b,gain_op,taken,before,after}], trace, final, ans`。
- 原 `lookup` 字段换成 `meta`（`START, OPS, N_LOSS, N_GAIN`）。Task B 的 `FIRST/LAST/TABLE_SIZE` 类约束在新题型下没有对应，需要重新设计。
- 和 pointer 版一样，**只把 `q` 发给模型**；`solution / chains / ans` 都含答案。

## 7. 风险与待验证

1. **p1 未知**：最大的不确定性。之前的"双寄存器条件更新"在 d=1 DA 只有 0.00–0.01，但那一版要求把两个寄存器编码成
   `A*100+B`，读出负担很重；新版只有一个数量、直接问"有多少"，预期好得多，但必须实测。
2. **CoT(20) 可能仍在天花板**：每步只是一次比较 + 两位数加减，CoT 可能 >0.9。如果 p1≥0.99，用第 3 节旋钮
   （更大 delta、小数）提难度。
3. **模板重复**：4 种条件句式 × 7 种减少动词 × 6 种增加动词，d=20 读起来很机械，但这正是"每步同构"的要求；
   GSM8K 的多样性（混合运算、汇总、步数分布）按之前的分析刻意不照搬。
4. **长度随 d 线性增长**：d=20 约 2200–2400 字符（约 550–650 token），长度与深度混杂，与 pointer 版同性质。
5. **阈值暴露近似状态**（见第 2 节），只影响"近似猜"，不影响精确答案。
6. **并行版多答案读出成本**仍是混杂因素，与 pointer 版相同。

## 8. 用法

在仓库根目录、用 uv 环境运行（只依赖标准库，但以仓库解释器为准）：

```bash
cd Experiments/task_a_wordproblem
uv run python generate.py --mode samples --show
uv run python generate.py --mode samples --decimals 2 --out samples_dec2.jsonl --show
uv run python generate.py --mode check --n 500
uv run python generate.py --mode calib --seed 1234 --out calib_int/calib_set.jsonl
uv run python generate.py --mode full --out full.jsonl    # 3000 题；校准通过并人工接受后再生成
```

`--ops` 只接受 `addsub`。传入 `mixed` 会被 argparse 拒绝。
校准怎么跑、结果怎么汇总，见本目录 `README.md`。
